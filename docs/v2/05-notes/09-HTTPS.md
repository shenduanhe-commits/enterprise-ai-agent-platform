---

## 1. HTTPS 是什么

HTTPS = HTTP 套在 **TLS** 里。浏览器和服务器先握手，再在加密通道里走原来的 HTTP（方法、路径、Header、Body）。

不是「全站一把锁、所有客户端共用同一套密文」。

| | 统一还是每客户端不同 |
| --- | --- |
| 网站证书（公钥） | 统一，谁都能看 |
| 网站私钥 | 只有服务器有 |
| 加密业务数据的会话密钥 | **每个 TLS 连接一份**，握手完才有，连接结束作废 |

旁路抓到你的密文，用别人那次连接的密钥解不开。

---

## 2. 私钥做了哪些工作

这里的私钥是**服务器证书配的那把**。它几乎只在 **TLS 握手**里干活；握手之后加密请求/响应的，是这次连接的对称会话密钥（如 AES）。

现代 TLS（1.2 的 ECDHE、以及 1.3）私钥主要做一件事：**签名，证明「我就是证书上的那个站」**。

浏览器拿到证书（里面是公钥）。服务器用私钥对握手数据签名，浏览器用公钥验签。验过了才相信对面不是假网站。会话密钥由双方用临时 ECDH 算出来，**不是用私钥加密后再传过去的**。

| 阶段 | 私钥做什么 |
| --- | --- |
| 握手 | 签名，证明身份 |
| 之后的 HTTP 请求/响应 | **不参与** |
| 绝不能做的 | 发给客户端、写进前端、提交进 Git |

老式 RSA 密钥交换里，客户端会用公钥把预主密钥加密传给服务器，服务器再用私钥解密。现在基本不用：私钥一旦泄露，以前录下来的流量也可能被解开。ECDHE 把「协商密钥」和「长期私钥」拆开，才有**前向保密**。

和本仓库 JWT 的差别：`JWT_SECRET` 是 HMAC **共享密钥**，签发和校验是同一把。HTTPS 证书是非对称：公钥公开，私钥用来**证明身份**，不是用来逐字节加密 Chat 正文。

## 3. 请求地址加不加密

不全是。加密的是 TLS 包里面的 HTTP，不是「你连哪台机器」。

```text
https://api.eaap.example/api/v1/agents/1/chat?debug=1
        └──── 主机名 ────┘└──────── 路径和查询 ────────┘
```

| 部分 | HTTPS 里加不加密 | 旁路抓包能看到什么 |
| --- | --- | --- |
| 对方 IP | 不加密 | 看得到，包必须送到这个 IP |
| 主机名 | 握手时的 **SNI** 通常是明文 | 多数情况看得到访问了哪个站 |
| 路径 `/api/v1/agents/1/chat` | 在 TLS 里面 | 看不到 |
| 查询 `?debug=1` | 在 TLS 里面 | 看不到 |
| Header、Body、Cookie | 在 TLS 里面 | 看不到 |

别人知道你在连哪台服务器、哪个域名，不知道你调了哪个接口、带了什么 token。

- 连 HTTPS 之前往往先做 DNS。普通 DNS 是明文，会露出域名；DNS over HTTPS 才能把查询也盖住。
- TLS 1.3 有 Encrypted Client Hello，可以把 SNI 也加密，尚未普及。

不要把秘密放在 URL 里。路径对旁观者不可见，但仍会进浏览器历史、服务器 access log、Referer。Token 放 `Authorization`，不要写成 `?access_token=`。

---

## 4. 抓包谁能看见明文

对**信道上的旁观者**，请求和响应内容都看不到。

| 谁 | 看不看得完明文 |
| --- | --- |
| Wi‑Fi 旁听、路由器镜像（HTTPS） | 看不到（只有密文） |
| 本地 HTTP（本仓库默认） | 头和 body 全是明文 |
| 浏览器开发者工具 Network | 看得到（数据在进 TLS 之前 / 出 TLS 之后） |
| FastAPI / Nginx | 看得到，解密发生在服务器上 |
| 本机 Charles / mitmproxy（装了证书） | 看得到，等于中间人参与了握手 |
| 公司 HTTPS 代理（设备信任了公司 CA） | 代理看得到 |

HTTPS 保证的是：**传输路上不被偷看、不被改**。两端本来就要读明文才能工作。Token 仍可能从浏览器、服务器日志、本机调试里漏出去，只是不会再以明文躺在网线里。

能解开 TLS 的抓包，该请求里有什么就能看到什么。双 token 挡不住这种人。Refresh 只是出现次数少（只在 `/auth/refresh`），不是抓包不可见。
